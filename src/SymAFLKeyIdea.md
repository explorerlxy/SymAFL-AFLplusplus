# Motivation
现有模糊测试器，主要依赖具体执行目标程序并收集coverage bitmap，来判断测试用例是否可以触发新的程序状态。这意味着，Mutator产生的每个测试用例，ForkServer都需要进行一次具体执行，然而事实上，在整个模糊测试的过程中，绝大多数测试用例都是低价值的（无法触发新的程序状态）。此外，真实世界中存在大量具备以下特征的真实软件：高计算负载、高IO负载、低逻辑分支数。针对这种软件，具体执行目标程序并收集coverage bitmap的效率很低，因为每次具体执行都会带来较高的计算和IO成本。也就是说，对于这种软件，通过具体执行的方式来判断测试用例的价值是非常低效的。
# Key Idea
于是，提出了基于轻量化动态符号执行的路径约束树引导的模糊测试器SymAFL。SymAFL配套的编译器基于SymCC扩展而来，在编译目标程序时，舍弃了维护Coverage Bitmap的桩代码，只植入收集路径约束序列的桩代码和类似Asan的漏洞检测分支逻辑。模糊测试器在测试过程中会将具体执行目标程序时收集的路径约束序列聚合为路径约束二叉树，并持续维护。测试过程中，对于Mutator生成的新测试用例，SymAFL会根据当前的路径约束二叉树，判断该测试用例是否可以触发新的程序执行路径（可能是原程序的路径，也可能是漏洞检测逻辑）。如果可以，则会直接加入到种子序列种，并交给ForkServer进行具体执行，收集新路径对应的路径约束序列。如果不可以，则直接舍弃该测试用例。这种新的测试范式，可以有效规避基于具体执行的种子筛选方法由于大量低价值测试用例而引入的高昂测试负载，同时从漏洞检测第一性原理（Reachability和Detectability）出发，对测试进行更有意义的引导。
